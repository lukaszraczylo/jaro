JARO

One JSON-compatible data model in two encodings. The text form uses fewer bytes and fewer LLM tokens than JSON or YAML. The binary form is the smallest and the fastest to decode. Libraries for Go, TypeScript and Python. Anchors, spreads, tables, comments and schema validation are part of the format.

The same files in TypeScript and Python

Each library is pure TypeScript or pure Python and is compared with the ecosystem's own JSON and YAML code: JSON.parse and the yaml package on Node 22, json and PyYAML with libyaml on Python 3.13. JAROB decodes faster than JSON.parse on all six files in TypeScript (0.13 to 0.95 of JSON time; twitter and recipe_book are within 6%). JARO text decodes 1.5 to 2.8x slower than JSON.parse in TypeScript and 1.5 to 6.1x slower than json in pure Python. In Python the optional Rust extension (jaro_native) decodes JAROB in 0.16 to 0.32 of json time; the pure Python JAROB decoder takes 0.6 to 4.8x. YAML decodes 18 to 164x slower than JSON.

Dataset detail

Absolute values for every format on one dataset. Bars are drawn to scale within each chart.

Measured by jaro/bench on 2026-10-11 (Go, macOS). Sizes are bytes of one document. gzip and zstd use default levels. Decode time is one full decode into any, except JARO Parse, which decodes into a flat document and appears for decode time and allocations only. JARO is the text form and JAROB the binary form. go-json is a faster JSON library, shown as the reference for tuned JSON. Tokens count the text form with the o200k_base tokenizer; the binary form has no token count. The real-world files are public corpora and live API responses that were not written for JARO.
